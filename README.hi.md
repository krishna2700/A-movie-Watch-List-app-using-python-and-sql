# मूवी वॉच लिस्ट ऐप

Python और SQLite के साथ बनाया गया एक कमांड-लाइन मूवी वॉचलिस्ट एप्लिकेशन। फिल्मों को ट्रैक करें, उपयोगकर्ताओं को प्रबंधित करें, और आपने क्या देखा है इसका रिकॉर्ड रखें।

## विशेषताएं

- **फिल्में जोड़ें** — रिलीज की तारीखों के साथ फिल्मों को स्टोर करें
- **आगामी फिल्में देखें** — भविष्य की रिलीज तारीखों वाली फिल्में देखें
- **सभी फिल्में देखें** — पूर्ण मूवी कैटलॉग ब्राउज़ करें
- **फिल्मों को देखा गया के रूप में चिह्नित करें** — ट्रैक करें कि प्रत्येक उपयोगकर्ता ने कौन सी फिल्में देखी हैं
- **उपयोगकर्ता प्रबंधन** — ऐप में उपयोगकर्ता जोड़ें
- **खोज** — आंशिक शीर्षक मिलान द्वारा फिल्में खोजें

## आवश्यक शर्तें

- Python 3.8+ (`app.py` में उपयोग किए गए walrus operator `:=` के लिए 3.8 या बाद का संस्करण आवश्यक है)

कोई बाहरी निर्भरता आवश्यक नहीं है। ऐप Python के अंतर्निहित `sqlite3` मॉड्यूल का उपयोग करता है।

## शुरुआत करना

1. **रिपॉजिटरी को क्लोन करें**

   ```bash
   git clone <repository-url>
   cd A-movie-Watch-List-app-using-python-and-sql
   ```

2. **एप्लिकेशन चलाएं**

   ```bash
   python3 app.py
   ```

   पहली बार चलाने पर डेटाबेस फ़ाइल (`data.db`) स्वचालित रूप से बनाई जाती है।

## उपयोग

जब आप ऐप शुरू करते हैं तो आपको एक इंटरैक्टिव मेनू दिखाई देता है:

```
कृपया निम्नलिखित विकल्पों में से एक चुनें:
1) नई फिल्म जोड़ें।
2) आगामी फिल्में देखें।
3) सभी फिल्में देखें
4) देखी गई फिल्म जोड़ें
5) देखी गई फिल्में देखें।
6) ऐप में उपयोगकर्ता जोड़ें।
7) किसी फिल्म को खोजें।
8) बाहर निकलें।
```

| विकल्प | विवरण |
|--------|-------|
| **1** | शीर्षक और रिलीज़ तारीख (`dd-mm-YYYY`) दर्ज करके फिल्म जोड़ें। यदि कोई तारीख प्रदान नहीं की गई है, तो आज की तारीख का उपयोग किया जाता है। |
| **2** | उन सभी फिल्मों की सूची बनाएं जिनकी रिलीज़ तारीख भविष्य में है। |
| **3** | डेटाबेस में प्रत्येक फिल्म की सूची बनाएं। |
| **4** | उपयोगकर्ता नाम और फिल्म ID प्रदान करके किसी फिल्म को देखे गए के रूप में चिह्नित करें। |
| **5** | किसी विशिष्ट उपयोगकर्ता द्वारा देखी गई सभी फिल्में देखें। |
| **6** | उपयोगकर्ता नाम द्वारा एक नया उपयोगकर्ता पंजीकृत करें। |
| **7** | आंशिक शीर्षक मिलान द्वारा फिल्में खोजें। |
| **8** | एप्लिकेशन से बाहर निकलें। |

## डेटाबेस स्कीमा

ऐप `data.db` में तीन टेबल बनाता है:

### `movies`

| कॉलम | प्रकार | विवरण |
|------|-------|-------|
| `id` | INTEGER (PK) | ऑटो-इंक्रीमेंटेड मूवी ID |
| `title` | TEXT | फिल्म का शीर्षक |
| `release_timestamp` | REAL | Unix टाइमस्टैम्प के रूप में संग्रहीत रिलीज़ तारीख |

### `users`

| कॉलम | प्रकार | विवरण |
|------|-------|-------|
| `username` | TEXT (PK) | अद्वितीय उपयोगकर्ता नाम |

### `watched`

| कॉलम | प्रकार | विवरण |
|------|-------|-------|
| `user_username` | TEXT (FK → users) | दर्शक का उपयोगकर्ता नाम |
| `movie_id` | INTEGER (FK → movies) | देखी गई फिल्म की ID |

कुशल आगामी-फिल्म क्वेरी के लिए `movies.release_timestamp` पर एक इंडेक्स (`movies_release_idx`) बनाया गया है।

## ज्ञात सीमाएं / भविष्य के सुधार

- **Python संस्करण** — walrus operator (`:=`) के कारण 3.8+ की आवश्यकता है। यदि आवश्यक हो तो व्यापक अनुकूलता के लिए रिफैक्टरिंग पर विचार करें।
- **कोई इनपुट सत्यापन नहीं** — अमान्य तारीखें, गैर-मौजूद उपयोगकर्ता नाम, या गलत मूवी ID से अनहैंडल्ड अपवाद उत्पन्न होंगे।
- **कोई डिलीट या एडिट नहीं** — एक बार जोड़े जाने के बाद फिल्मों और उपयोगकर्ताओं को अपडेट या हटाया नहीं जा सकता है।
- **डुप्लिकेट वॉच** — एक उपयोगकर्ता एक ही फिल्म को कई बार देखे गए के रूप में चिह्नित कर सकता है; `watched` टेबल पर कोई विशिष्टता बाधा नहीं है।
- **विदेशी कुंजी प्रवर्तन** — SQLite विदेशी कुंजियां परिभाषित हैं लेकिन रनटाइम पर लागू नहीं की जाती हैं (`PRAGMA foreign_keys` सक्षम नहीं है), इसलिए अनाथ संदर्भ संभव हैं।
- **कोई पेजिनेशन नहीं** — बड़ी मूवी सूचियां बिना पेजिंग के पूर्ण रूप से प्रिंट की जाती हैं।
- **हार्डकोडेड DB पथ** — डेटाबेस फ़ाइल हमेशा वर्तमान कार्य निर्देशिका में `data.db` होती है; इसे पर्यावरण चर के माध्यम से कॉन्फ़िगर करने योग्य बनाने पर विचार करें।
- **कोई टेस्ट नहीं** — परियोजना में अभी तक कोई स्वचालित परीक्षण सूट नहीं है।
